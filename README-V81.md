# AJK Bola Wawei AI V8.1 — Hybrid ML (shadow release)

## Install (Windows)
1. Download latest main ZIP from https://github.com/ahmcsec-lgtm/fpl-ai-analyst-Copy and extract. Use the inner folder containing app.py and learning_dashboard.py. Back up repository first.
2. Copy all files from this upgrade into that folder (including hidden .github/workflows/ai-learning-v81.yml). Do not remove V8.0 or other workflows.
3. Run `py -3 install_v81.py`. Only learning_dashboard.py is modified, with a .v80-backup. app.py, fpl_engine.py and requirements.txt are untouched. The existing AI Performance tab gets a new section even when V8.0 has no matched forecasts.
4. Run `py -3 -m streamlit run app.py` using the environment where V8.0 worked. For local ML tests/training use Python 3.11 or 3.12: `py -3.11 -m pip install -r requirements-v81.txt`, `py -3.11 -m unittest test_ml_v81`. Optional local training: `py -3.11 ml_v81.py train` (downloads historical CSVs to .v81-cache). Do not upload cache or backup.
5. Upload learning_dashboard.py (modified), ml_dashboard_v81.py, ml_v81.py, install_v81.py, requirements-v81.txt, test_ml_v81.py, README-V81.md to root of main. Upload ai-learning-v81.yml into .github/workflows. Do not replace V8.0 workflow. Commit changes.
6. Actions > AI Learning V8.1 > Run workflow > main. Inspect test, collector, auto and commit logs. Expect Imported <season>, Trained <version> historical gate ..., commit. Check data/learning_v81/model.json and models/<version>/*.txt. If fewer than 3 valid seasons, training fails and existing models remain. If a workflow push conflict occurs, rerun from main; no force push.
7. Open online app > AI Performance, refresh or reboot if needed. The historical validation should appear even before any live matched forecast. A historical gate failure is an expected valid result, not an installation error. Existing V8.0 remains active.
8. Scheduled runs are 02:47, 08:47, 14:47, 20:47 MYT, subject to GitHub scheduling. The V8.1 workflow also invokes the V8 collector to avoid missing a snapshot; both workflows share the V8 concurrency group. GitHub can cancel pending runs when multiple queue; verify schedules. Train first run and every 30 days thereafter; historical data is fixed to 2020-21 through 2024-25, not incremental learning from current results. Live forecasts appear only while a V8 forecast is available and the deadline has not passed. Do not backdate snapshots.

## Model and limitations
- Source: https://github.com/vaastav/Fantasy-Premier-League (credit Vaastav and contributors). CSVs are downloaded at runtime; no third-party dataset is bundled. SHA256 of each imported CSV is recorded. Check source terms before redistribution.
- Historical player-fixture rows are aggregated by season-local player ID and GW. Single-fixture GW targets only, prior 3/5 eligible observations, points/minutes/goals/assists/clean sheets/bonus, position. No target-match statistics used as inputs. History excludes the immediately preceding GW. Historical kickoff-based cutoff proxy: earlier GW last kickoff + 2 days must precede target first kickoff - 2 days. This is not a verified historical FPL deadline or finalization timestamp. Historical schedule changes, missing players, position changes and scoring rule changes may bias results. Live cutoff uses actual observation timestamps at V8 capture.
- Expanding season walk-forward: first two valid seasons train, each subsequent season held out in turn. Fixed model hyperparameters, RMSE/MAE/bias. Historical baseline = last 5 eligible observations, NOT V8.0 engine. Separate xP and minutes regressors. Gate requires strictly lower RMSE in all folds, independently per target. Then retrain on all accepted seasons. No claim of improvement until tested on real data.
- Shadow blend 75% V8.0 + 25% ML when eligible and gate passes; otherwise 100% V8.0. No ML for doubtful/unavailable status, insufficient history, or multi-fixture GW. Blended minutes are an independent comparison, not an input to the xP regressor. No changes to transfer, captain, chip, team-rating or multi-GW calculations. No fixture-specific ML features; original model contributes fixture/availability information to the blend. No automatic promotion; evaluate several prospective GWs and scoring changes before integrating. FPL history used in historical training may differ in scoring and coverage from 2026/27. Current season actuals are used for live lagged features and evaluation, not retraining weights. Forecasts are frozen separately before deadline, model version recorded. Missing artifacts or invalid model fall back to existing recommendations. Streamlit only reads JSON; no ML package required in app runtime.
- Costs: no paid API; GitHub Actions and Streamlit subject to limits. Models are native text files, not pickle. Old versions retained for audit; monitor repository growth. No credentials needed beyond normal workflow token.
- Rollback: restore learning_dashboard.py.v80-backup locally and upload as learning_dashboard.py, disable AI Learning V8.1 workflow. Keep V8.0 workflow. No changes to original prediction engine to undo.
- Tests in this delivery use synthetic data, not actual FPL data. Historical download, live FPL API, full Streamlit integration and GitHub Actions deployment must be verified in your environment.
