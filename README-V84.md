## Baseline and installation
This patch is built from the previously delivered V8.3.5 app.py and V8.3 engine (not a byte-verified current GitHub checkout). Extract to a separate folder, e.g. Downloads\V84. Stop Streamlit. In the existing repository terminal, run:

```powershell
py -3.11 "$env:USERPROFILE\Downloads\V84\install_v84.py" .
py -3.11 -m pip install -r requirements.txt -r requirements-v81.txt -r requirements-v82.txt
py -3.11 -m unittest -v test_monte_carlo_v84 test_ui_v835 test_ui_v834 test_ui_v833 test_ui_v832 test_ui_v831 test_decision_v83 test_milp_v82 test_fast_greedy_v821 test_engine test_learning_v8 test_ml_v81
py -3.11 -m streamlit run app.py
```

The installer verifies both baseline source hashes (normalizing CRLF), refuses to overwrite differing local code, and creates a sibling backup directory. Do not bypass a baseline mismatch. On failure restore the two original files from the backup; remove new files if desired. Existing data, requirements, models, workflows and theme configuration are untouched. Upload the seven files listed in `install_v84.py` FILES in a single commit after local tests pass. The new workflow requires the previous tests and dependencies already in the V8.3.5 repository. No paid API. NumPy is already in the V8.1 dependencies.

## Decision method
After the existing legal beam search and deterministic contingency lineup selection, simulate 10,000 paired outcomes for each retained state. Reuse player-week and team-week random draws across plans. The reference is the best roll-first plan under the original V8.3 score; it may include future transfers. All candidates are ranked using the original decision score minus a bounded uncertainty margin, computed from mean-centered downside of simulated paired point differences. Weights: Safe .22, Balanced/Auto AI .12, Aggressive .04; cap 2.5 decision-score units. This is additional uncertainty aversion, not a deduction from reported points. Existing downside stress, free-transfer value, churn and adaptive margin remain. Hits are deducted once in simulated net points and once in the separate deterministic expected-points calculation. Simulation does not overwrite deterministic xP. A fixed seed gives reproducible draws in a fixed numerical environment. Lineups, captain and bench order remain chosen before the simulation; no hindsight selection.

The player model uses existing heuristic probability of any appearance, existing unconditional xP, a conditional minutes beta multiplier, a shared club-week gamma multiplier and independent player-week gamma noise. It is a nonnegative continuous points proxy, not exact FPL scoring. No explicit goal, assist, clean-sheet event, opponent correlation, cross-week injury persistence, exact DGW minutes or calibrated probabilities. The minutes proxy is per fixture, while appearance/xP are per GW. Zero-appearance/positive-xP conflicts trigger fallback. Existing manual minutes and risk strategy inputs are retained. Legal auto-sub uses the same positional replacement convention as V8.3; GK is separate and VC inherits captain bonus only if captain does not play. This is fixed itinerary evaluation, not adaptive scenario-tree optimisation. No full-market Monte Carlo search or guarantee of global optimum. ML remains shadow-only. Risk metrics are internal; only a short status line is added to existing Why this decision? and the cache version is bumped.

The Monte Carlo phase has a cooperative five-second deadline and per-analysis caches; it cannot interrupt a single running NumPy call. On any simulation error or timeout, the complete V8.3 ranking is used (no mixed scoring). The existing candidate search and API calls are outside this time budget. No promise of five-second total loading. See test-results-v84.log and benchmark-results.log. Offline run: 71 tests, 69 passed, 2 skipped (PuLP/highspy not installed); actual Streamlit rendering not exercised. 300 synthetic players, six GWs, beam width 4, candidate count 5, no MILP seeds: 3.470s total, 16 plans simulated. An 800-player default-search benchmark did not finish within the available execution budget; production latency remains unverified. Run `py -3.11 benchmark_v84.py` for the included reduced benchmark. The simulated risk weights require live decision backtesting before being treated as validated.
